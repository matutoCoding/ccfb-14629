# 近海网箱双目测鱼系统（仿真先行）

浏览器端大黄鱼深水网箱双目测量原型。TypeScript + React + WebGPU，数据保存在 IndexedDB；当前用程序化水下鱼群和折射/畸变相机跑通“建档 → 标定 → 双目采集 → 立体测量 → 对账 → 生长/投喂分析”，以后可把仿真采集源替换成真实双目相机。

## 启动

```bash
npm install
npm run dev
```

打开 Vite 输出的地址（默认 http://localhost:5173）。生产构建：

```bash
npm run build
npm run preview
```

无显示环境或浏览器不支持 WebGPU 时，画面会自动切到 Canvas2D 渲染同一批投影几何，测量算法不变。

## 精度自检

```bash
npm run selftest
```

该脚本不依赖浏览器，直接运行仿真鱼、玻璃折射、Brown–Conrady 畸变、立体三角测量、中轴平滑和对账。最近一次开发机结果（620mm 基线、5.8mm 镜头、0.05px 仿真检测噪声）：

- 正确几何参数：MAPE 约 **1.0%**
- 经棋盘格 LM 标定后：MAPE 约 **1.0%**
- 故意把基线设为 **−3%**：平均偏差约 **−2.8%**，误差不会被平滑或隐藏
- 页面“设置 → 测量精度自检”可在浏览器里跑同样的对照

> 视觉关键点噪声、鱼群位置和标定角点噪声都是仿真参数。真实相机接入后，精度首先取决于水下标板、双目标定、同步和关键点/匹配质量。

## 已实现页面

1. **网箱档案**：12 口示范网箱；周长、网深、放苗日期、苗种、尾数、成活率；每口箱 1–2 台双目相机，记录安装深度、方位、yaw/pitch/roll、基线、焦距、传感器、玻璃罩参数和故意偏差。
2. **相机标定**：一次生成 14 组水下棋盘格，其中 1 组预置运动模糊/误检；DLT 单应初值 + Levenberg–Marquardt 优化 fx/fy/主点/k1/k2/k3 和每组 rvec/tvec；逐张左右 RMS、最大误差；可勾选剔除或一键剔除最差组并重算，保存为标定档案。
3. **双目画面**：默认 DHY-01 挂 A/B 两组双目，共 4 路 WebGPU 画面；程序化大黄鱼按正态体长生成，11 节骨骼摆尾，绕箱巡游，靠近镜头会内避；水色、浑浊度和光照随时辰/水深变化。支持：
   - 左目点吻端/中轴/尾叉，右目沿广义极线（考虑畸变和玻璃折射的采样曲线）匹配；
   - 弯曲鱼身用 11 个中轴点三角化、二次曲线平滑后加密累计弧长；
   - 自动挑选侧身、整条入画、低遮挡鱼，输出斜角、遮挡率、可信度和跳过原因；
   - 每条测量与仿真真值对账，显示误差 mm/% 和整体 MAPE/系统偏差。
4. **测量记录**：IndexedDB 持久化、网箱/方式/ID 筛选、CSV 导出。
5. **生长分析**：叉长直方图、平均体长/体重、样本量不足提示、按日期的生长曲线、日增重 ADG、上市规格倒计时、存鱼生物量和水温修正投喂量。
6. **设置**：季节长重系数 `W=aL^b`、上市规格、自动选鱼阈值、噪声、投喂率、WebGPU/低分辨率开关、精度自检和示范数据重置。

## 关键目录

```text
src/
  lib/
    camera.ts        # 相机模型、Snell 玻璃折射、Brown 畸变、射线反投影、三角测量、广义极线
    calibration.ts   # 棋盘格生成、DLT、LM 标定、立体外参平均
    db.ts            # IndexedDB
    growth.ts        # 长重、ADG、上市预测、投喂、统计
    seed.ts          # 12 口网箱、相机和历史测量
  sim/
    world.ts         # 鱼群、骨骼游泳、绕箱、躲避、水况
    batch.ts         # 同一相机模型驱动的鱼体/网衣/粒子几何
    renderers.ts     # WebGPU 与 Canvas2D 后端
    measure.ts       # 自动选鱼、极线匹配、三角测量、中轴平滑、对账
  components/        # CameraCanvas、图表、UI
  pages/             # 六个业务页面
scripts/selftest.ts  # Node 精度回归
```

## 接真相机时的替换点

- 用真实双目帧替换 `CameraCanvas` 的 `buildCameraBatch()` 仿真源；
- 标定页的角点检测可替换成真实棋盘格/ChArUco 检测，标定优化器和数据结构可继续使用；
- `buildKeypointCandidates()` / `matchRightAlongEpipolar()` 替换成真实鱼体关键点和立体匹配；
- 测量记录、生长分析、投喂推荐和 IndexedDB schema 不需要重做。
